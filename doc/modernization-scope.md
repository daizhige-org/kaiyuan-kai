# 现代化范围评估：离「一套现代简体中文字体应有的功能」还差什么

本项目的本质是利用文鼎两套旧字体的现成字形，做出一套**现代化**的简体中文
楷体。这份文档回答一个问题：以现行标准（《通用规范汉字表》2013、GB/T
15834-2011《标点符号用法》、Adobe/思源系 CJK OpenType 惯例、W3C CLReq 中文
排版需求）衡量，目前的缺口在哪里、各有多大。所有数字都是对当前
`kaiyuan-kai-sc.ttf` 实测所得。

## 一、字集覆盖与字形规范（最重要的一项）

以《通用规范汉字表》8,105 字为基准：

| | 字数 | 说明 |
|---|---:|---|
| 已覆盖 | 7,809 | 96.3% |
| 其中来自简中楷（中国大陆规范字形） | 6,638 | 字形正确 |
| **其中来自 UKai（台湾字形）** | **1,171** | **字形不符合大陆规范** |
| 完全缺失 | 296 | 多为三级字表生僻字（㕮㙍㙘…） |

这是当前最大的结构性缺口，也是「原来写给 UKai 的规则，现在字形换了 GB 的，
规则也应该重写」这一原则最直接的体现：**合并规则只保证了「有」，没有保证
「对」**。1,171 个规范字来自 UKai，其笔形沿用台湾《国字标准字体》惯例
（辶 两点、艹 分离、户/戶、骨 上部朝向等），与简中楷部分的大陆字形在同一套
字体内混用，对面向大陆用户的字体而言属于不一致。

可能的处理方向（工作量递增）：

1. 逐字核对这 1,171 字，找出其中在两岸字形上确有差异的子集（并非全部 1,171
   字都有差异，很多生僻字两岸写法一致），只对有差异者做处理。
2. 对有差异者，在 UKai 字形基础上按大陆规范修改部件（部件级替换，如统一把
   台式 辶 换成大陆式）。这是字形层面的工作，需要字体设计判断，不是脚本能
   自动完成的。
3. 296 个完全缺失的字：属于新增字形，无现成来源，只能新画或从其他许可证兼容
   的字体补入。

## 二、标点符号（GB/T 15834-2011）

已完成：破折号/省略号接续、句读符号与引号的纵向位置、`halt` 半宽压缩特性
（见 `punctuation-placement.md`）。

尚缺：

- **`palt`（比例宽度替代）**：现代 CJK 字体通常与 `halt` 成对提供，思源系
  两者都有。目前只有 `halt`。
- **`chws`（上下文半宽间距）**：这是较新的特性，浏览器已通过 CSS
  `text-spacing-trim` 属性直接调用，用于相邻标点的自动挤压。目前没有。
  实现难度高于 `halt`，需要写上下文规则而非逐字形固定值。
- **横排标点的完整性检查**：GB/T 15834 规定的全部符号（间隔号「·」、连接号
  「–」、着重号等）是否全部有字形、位置是否正确，目前只核对了最常用的十几个。
- 已知小缺陷：`ń`、`ň` 在 cmap 中声明但轮廓为空（UKai 上游数据缺失），
  影响拼音第二、三声的 n 独立音节（「ń」「ň」在拼音方案中有用）。除此之外
  拼音全部 39 个带调字母都有正确字形。

## 三、竖排（中文竖排）

现状：`vhea` 只是一个对称占位值（512/-512/0），没有任何竖排替代字形，
`VORG` 已丢弃。**目前这套字体不能正确竖排。**

UKai 原有的 `vert` 特性有 26 条规则，其中 18 条的基础字形来自 UKai、可以
接回来；但这 26 条是按繁体/日语竖排惯例写的，不是按 GB/T 15834 的竖排规定。
GB/T 15834 对简体竖排有明确要求：句号、逗号、顿号置于字格右上；引号在竖排
中改用「」『』；书名号、括号旋转 90°；破折号、省略号竖向。这些与 UKai 的
规则并不完全一致。

按本项目原则，正确做法不是接回 UKai 的旧规则，而是：

1. 按 GB/T 15834 竖排规定，重新确定需要竖排替代字形的标点清单。
2. 用现有横排字形旋转/平移生成竖排字形（与破折号/省略号的处理方式一致：
   不新画，只做几何变换）。
3. 重写 `vert`（以及 `vrt2`）GSUB 规则。
4. 给 `vhea`/`vmtx` 填上真实数值，恢复或重建 `VORG`。

这是一个独立且工作量不小的子项目，需要先确认是否纳入范围。

## 四、OpenType 特性总览

| 特性 | 用途 | 现状 |
|---|---|---|
| `halt` | 半宽标点 | ✅ 已有（自写，数值取自 Hiragino Sans GB） |
| `palt` | 比例宽度标点 | ❌ 缺 |
| `chws` | 上下文标点挤压 | ❌ 缺 |
| `vert` / `vrt2` | 竖排替代字形 | ❌ 缺（见第三节） |
| `vpal` / `vhal` / `vchw` | 竖排标点压缩 | ❌ 缺 |
| `mark` / `mkmk` | 组合附加符号定位 | ⚠️ 可从 UKai 恢复；实测 HarfBuzz 优先使用预组合字形，实际触发场景少 |
| `ccmp` | 字形组合/分解 | ❌ 缺 |
| `locl` | 按语言选字形 | ❌ 缺；对单语言（zh-Hans）字体非必需，但若保留 UKai 台湾字形可用它区分 |
| `kern` | 西文字距 | ❌ 缺 |
| `frac` / `fwid` / `liga` | 分数 / 全角化 / 连字 | ❌ 天生用不上：影响的基础字形全部来自简中楷，UKai 的规则无处可套 |

关于 `frac`/`fwid`/`liga`：重新跑一遍不丢弃排版表的子集化流程后确认，这三个
特性所影响的字形（数字、8 个符号、「招財進寶」合文（UKai 中该合文由繁体字形组成））全部落在简中楷已覆盖的
码位内，字形来自简中楷而非 UKai，子集化工具会因找不到对应的 UKai 基础字形而
自动剪掉这些规则。这不是主动丢弃，而是合并规则的必然结果；若要保留，需要
额外从 UKai 复制这些基础字形的 UKai 版本并重新挂接规则，收益极小。

## 五、西文

- 基本拉丁字母全部是 **512 单位等宽（半角）**，`i`、`W`、`m` 宽度相同，
  是打字机式设计，与现代字体的比例西文差距明显，中英混排时尤其突出。
- 没有 `kern` 表，也没有 GPOS kern 特性。
- 风格与楷体笔意不搭（此前已讨论过；换用 OFL 字体存在许可证冲突，见
  `README.md`）。

这一项的根本限制是：文鼎两套字体都没有一套像样的比例西文，现有材料里没有
可以直接拿来用的东西。可选方向只有：找许可证兼容（非 copyleft）的西文并入，
或者维持现状。

## 六、技术层面

- **`OS/2` 表版本为 1**，而 `fsSelection` 的 `USE_TYPO_METRICS` 位（bit 7）
  只在版本 4 及以上有定义。目前该位虽已置位但按规范属于未定义状态；由于
  `hhea`/`OS/2` typo/win 三处数值已统一，实际不影响行高，但应升级到版本 4
  并补齐相应字段。
- **Hinting**：全字体仅 930 个字形带 TrueType 指令，且几乎全是简中楷的西文
  字母；汉字均无 hinting。这套 1990 年代的指令对现代高分屏渲染意义有限，
  可以考虑整体去除以求一致（我们改动过的标点字形已无指令）。
- 缺 `cmap` format 14 子表，即不支持 IVS（异体字选择器）。对单语言简体字体
  非必需，但思源系现代字体均有。**注意：此前 README 曾误称 UKai 有 IVS，
  实测 UKai 本身就没有，应更正。**
- 单一字重，无可变字体轴。源材料只有一个字重，无法在不新画的前提下扩展。

## 七、建议的优先级

1. **字形规范（第一节）**——直接决定这套字体作为「大陆规范楷体」是否成立，
   优先级最高，但也是工作量最大、最需要字体设计判断的一项。建议先做第 1 步
   （找出确有两岸差异的子集）把问题规模量化。
2. **竖排（第三节）**——明确的功能缺失，规则清晰（GB/T 15834），字形可由
   横排字形几何变换得到，实现路径与已完成的标点工作一脉相承。
3. **`palt` / `chws`（第二节）**——补齐现代 CJK 字体的标准特性集，`palt` 可
   参照 `halt` 的做法快速完成，`chws` 稍复杂。
4. **`OS/2` 升版、`ń`/`ň` 补字形、hinting 统一（第六节）**——小修，随手可做。
5. **西文（第五节）**——受许可证和源材料限制，短期内无好办法，暂缓。
